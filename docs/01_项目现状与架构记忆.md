# SAP B1 通用可靠审批中心 - 项目现状与架构记忆 (Project Memory)

---

## 一、项目核心背景与业务现状

### 1. 业务痛点
公司使用 SAP Business One 10.0 SQL Server 版，并通过一套第三方无源码辅助开发平台搭建了“型号订单 `CHORDR`”、“型号报价单 `CHOQUT`”等大量业务功能。此前由于缺乏统一的审批机制，单据保存后容易直接进入后续转单或生产环节，存在内控风险。

### 2. 核心诉求
- 为型号订单增加可配置审批流程；
- 具备类似 BPMN 的强可配置性（条件网关、串行、并行、会签/或签、转交、退回、超时升级）；
- 提供现代化的 Web / 移动端审批门户，并支持通知提醒；
- 在辅助平台无源码的约束下，实现顺畅的客户端交互与下游防绕过。

## 三、第三方辅助平台黑盒约束与交互决策

### 1. 平台硬限制
- 平台无源代码，无法修改其内部事件处理；
- 网页 DOM 无法直接调用 SAP UI API 打开客户端自定义窗口；
- 网页无法直接通过 JS Bridge 刷新 SAP 界面。

### 2. 平台已具备的能力
- 动态为 Web 浏览器控件赋值 URL；
- 表格支持“文本框（带链接）/ 黄箭头”，可按当前行 `DocEntry` 穿透打开标准/自定义单据。

### 3. 落地交互闭环
- **单据内嵌模式**：从型号订单窗口点击按钮，动态加载内嵌审批页；
- **工作台联动模式**：无对象窗口左侧为待办查询表格（带黄箭头），右侧为 Web 审批页，点击黄箭头即可在 SAP 客户端内穿透打开原始单据；
- **显式提交原则**：禁止页面加载即自动提交，必须由用户显式点击触发。

## 四、核心架构可靠性规范

1. **规范化快照与 SHA-256 防篡改 (`CanonicalSnapshotBuilder`)**：
   - 提交时服务端抓取单据递归排序列化为 Canonical JSON 并生成 SHA-256 签名，审批放行前校验哈希，杜绝流转期间数据篡改。
2. **Outbox 事务发件箱模式 (`OutboxRelayWorker`)**：
   - 本地单库事务持久化 + 后台异步中继回写 SAP Service Layer，消除分布式事务死锁，网络闪断自动补偿。
3. **字段变更免审分级 (Delta Whitelist)**：
   - 免审白名单字段（如备注、物流单号、打印计数）修改直接放行，仅留存审计日志；核心敏感字段（单价、数量、总金额、客户）修改立即熔断重新审批。
4. **跨架构支持**：
   - 原生支持 Windows x64 与 ARM64 跨架构一键编译与分发。
