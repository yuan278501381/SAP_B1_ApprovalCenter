# 当前实现状态与生产落地清单

更新日期：2026-08-15。

## 1. 本轮已补齐

Gemini 初版能构建和演示，但存在 API/Worker 使用隔离内存库、URL 冒充审批人、Return 悬空、默认流程版本外键无效、Outbox Processing 永久卡死、SQL DDL 与 EF 列名不匹配等问题。本轮已完成：

- 取消隐式默认流程，只允许已发布且已绑定版本；
- 支持条件节点出现在开始或审批节点之后，检测循环和无后续连线；
- 候选审批人服务端校验；
- Return 结束当前实例并发出 `InstanceReturned`；
- API 写操作要求幂等键，并在 SQL 模式下把业务写入与 Inbox 放进同一事务；
- 每张单据只允许一个 Running 实例的数据库唯一约束；
- EF 全量映射为 DDL 使用的 snake_case；
- Outbox 五分钟租约恢复、`rowversion` 抢占、指数退避和同步状态记录；
- 最终回写 `Approved` 前重新拉取 SAP 单据并比对快照哈希；不一致时禁止放行并进入重试/告警；
- Worker 强制使用与 API 相同的 SQL ApprovalDB，不允许独立 InMemory；
- Service Layer 登录、401 重登、UDO GET、镜像 PATCH 的可配置 Adapter；
- 网关身份头认证、CORS 白名单、开发/生产身份模式隔离；
- 前端补齐幂等键、退回动作、相对 API 地址和生产静态托管。

## 2. 生产启用前必须完成

### SAP 元数据验证

1. 用 Service Layer `$metadata` 确认 `CHORDR`、`CHOQUT` 的实际 EntitySet。
2. 确认 Document UDO 的键是数字 `DocEntry` 还是字符串 `Code`。
3. 确认金额、标题、Creator、子表集合的真实字段名。
4. 在测试公司库创建并确认 `U_APStatus`、`U_APInstance`、`U_APHash`，或修改配置映射到批准的 UDF。
5. `MirrorEnabled=false` 完成只读拉取 PoC；验收后再开启 PATCH。

### 身份与权限

1. 选择 AD/LDAP/OIDC/企业门户中的一种统一认证。
2. 反向代理必须清除外部 `X-Approval-*` 头并注入认证身份。
3. API 端口只允许反向代理和运维网段访问。
4. 建立 SAP 用户码与统一身份账号映射；当前 Direct 候选值必须是映射后的稳定账号。

### 业务门禁

审批网页不能直接禁用无源码辅助平台上的按钮。因此必须逐一列出“生成标准订单、转生产、出库、采购”等放行动作，并在其服务端入口验证审批实例、状态和快照哈希。无法修改的入口，评估在 `SBO_SP_TransactionNotification` 中做最小门禁；上线前只提供评审 SQL，不直接修改生产存储过程。

### 数据库与运维

1. 在独立 `ApprovalDB` 执行 01；若已执行 Gemini 旧版脚本，再执行 02。
2. 配置 SQL 最小权限账号、备份、恢复演练和 TLS。
3. API 与 Worker 使用同一连接串；至少各部署一个实例。
4. 对 `wf_outbox.status='Failed'`、积压量、最老 Pending 时长、SAP 登录失败建立告警。
5. 用真实 SQL Server 跑并发提交、并发审批、Worker 中途崩溃和 SAP 断网恢复测试。

## 3. 下一阶段建议顺序

1. `DB_KCC` Service Layer 只读元数据/单据 PoC。
2. ApprovalDB SQL 集成测试（当前自动测试使用 InMemory）。
3. 统一认证与用户映射。
4. SAP 镜像 UDF + 下游业务门禁。
5. 通知中心。
6. 角色/主管选人、转交/委托、超时升级。
7. 会签和并行网关；最后再评估是否需要 BPMN 设计器。

## 4. 无辅助平台源码下仍然做不到的事

- 网页 JavaScript 直接调用 SAP UI API、刷新当前 SAP Form 或在客户端中打开任意自定义窗口；
- 给辅助平台新增安全的 JS→SAP 命令桥；
- 仅靠隐藏 SAP 按钮保证服务端权限；
- 在不知道辅助平台保存/更新事件机制时，保证“用户点击添加后自动提交审批”。可采用单据 Web 页中的“发起审批”按钮，或由定时服务扫描待提交状态。

可复用的闭环是：SAP 动态 URL 打开审批网页；网页显示状态和明细；SAP 表格黄箭头打开原单；审批后用户点击现有刷新按钮获取镜像状态。
