# SAP B1 10.0 通用审批平台世界级 DevOps 部署与运维手册

本手册指导如何将通用审批平台部署到 Windows Server、Docker 容器化环境，并完成自动化 CI/CD、数据库热备与全链路监控配置。

---

## 1. 部署拓扑与架构全景 (System Architecture)

```text
[SAP B1 客户端 (内嵌 Web 控件)]
       │
       ▼ (HTTP/HTTPS)
[Nginx 网关 / 反向代理 (端口: 80/443)] ──(剥离外部伪造头)──► [Approval.Api (端口: 5000)]
                                                                  │
                                                                  ├─► [ApprovalDB (SQL Server 2022)]
                                                                  │
[Approval.Worker 异步调度守护进程] ────(Outbox 轮询 & 租约保护)──────┤
       │
       ▼ (REST / OData v4)
[SAP Service Layer (端口: 50000)] ────► [SAP 业务公司库 DB_KCC]
```

### 运行环境基准：
* **操作系统**：Windows Server 2019/2022/2025、Linux (Ubuntu/Debian/RHEL)、Windows 10/11
* **CPU 架构**：原生支持 **x64** 与 **ARM64**
* **运行时**：.NET 8.0 Runtime (ASP.NET Core Hosting Bundle) / Docker 24+
* **数据库**：Microsoft SQL Server 2019 / 2022（ApprovalDB 独立库物理隔离）
* **SAP 端**：SAP Business One 10.0 SQL Server 版，Service Layer 运行正常

## 2. 三大生产部署模式 (Multi-Form Factor Deployment)

### 模式 A：Windows Server 原生服务一键自动化部署 (推荐用于虚拟机/现场单机)
以管理员身份打开 PowerShell，执行：
```powershell
pwsh deploy/deploy-to-server.ps1 -TargetServer 192.168.134.9 -ServicePort 5000
```
**全自动流水线动作**：
1. 执行质量门禁与测试套件；
2. 编译前端 Vue 3 并在 API 下集成 `wwwroot`；
3. 检查并初始化 `ApprovalDB`（包含表结构、并发唯一索引与用户组织树种子）；
4. 注册 `ApprovalPlatformApi` 与 `ApprovalPlatformWorker` 为开机自启 Windows 服务并启动；
5. 自动配置 Windows 防火墙入站规则。

---

### 模式 B：Docker Compose 现代化容器化部署 (推荐用于云端/K8s/容器集群)
在项目根目录下执行：
```bash
docker compose -f deploy/docker-compose.yml up -d --build
```
**包含容器组件**：
* `approval-api`：API 服务与前端静态托管，配置了 15 秒间隔的 `/health` 存活性探针；
* `approval-worker`：Outbox 异步状态同步守护进程；
* `nginx-gateway`：企业级安全网关，自动剥离外部伪造的 `X-Approval-*` 头，支持 Gzip 压缩与静态资源强缓存。

---

### 模式 C：跨架构 CI/CD 自动化流水线 (GitHub Actions / GitLab CI)
工作流文件位于 [`deploy/ci-cd.yml`](file:///C:/repo/SAP_B1_ApprovalCenter/deploy/ci-cd.yml)：
1. **并行测试矩阵**：在 Windows 和 Ubuntu 上并行执行全量单元与集成测试；
2. **多架构打包**：自动输出 `win-x64`、`win-arm64`、`linux-x64` 三种架构的绿色 `.zip` 发布包；
3. **容器镜像验证**：使用 Buildx 验证多架构 Docker 镜像构建。

## 3. 数据库备份与灾难恢复 (Disaster Recovery)

数据库运维脚本位于 [`deploy/backup-and-restore.ps1`](file:///C:/repo/SAP_B1_ApprovalCenter/deploy/backup-and-restore.ps1)：

### 执行热备份 (带压缩与校验和)：
```powershell
# 执行全量热备份
pwsh deploy/backup-and-restore.ps1 -Mode Backup -BackupType Full -SqlServerInstance 192.168.134.9

# 执行差异备份
pwsh deploy/backup-and-restore.ps1 -Mode Backup -BackupType Diff -SqlServerInstance 192.168.134.9
```

### 一键灾难恢复：
```powershell
pwsh deploy/backup-and-restore.ps1 -Mode Restore -SqlServerInstance 192.168.134.9
```

## 4. 全链路可观测性与健康监控 (Observability & Health Checks)

### 1. 服务健康检查探针
* **端点地址**：`GET http://<服务器IP>:5000/health`
* **响应**：`200 OK (Healthy)`，自动探测与 `ApprovalDB` 的 SQL Server 连通性。

### 2. 全链路 TraceID 追踪
* 所有 API 请求与响应头均包含 `X-Trace-Id`；
* 所有的审批流转日志（`wf_action_log`）和 Outbox 消息均持久化关联该 `TraceID`，可通过以下 SQL 精准排查单据全生命周期轨迹：
```sql
USE ApprovalDB;
SELECT * FROM wf_action_log WHERE trace_id = 'your_trace_id_here' ORDER BY action_time;
```

## 5. 数据库脚本编码与执行规范

> [!IMPORTANT]
> 项目中所有针对 SQL Server 的 `.sql` 脚本均严格遵循 **GBK 编码**，防止在 SAP 客户端报错弹窗中出现中文乱码：
> 1. `database/01_init_approval_db.sql`：数据库 DDL 与并发约束；
> 2. `database/02_upgrade_reliability.sql`：租约字段升级；
> 3. `database/03_gatekeeper_transaction_notification.sql`：TransactionNotification 业务门禁；
> 4. `database/04_create_sys_user_mapping.sql`：组织架构与统一用户映射。
